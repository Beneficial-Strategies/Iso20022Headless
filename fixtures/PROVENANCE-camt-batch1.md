# Provenance of the camt batch 1 fixtures

camt.053.001.14, camt.052.001.14, camt.054.001.14, camt.056.001.12, camt.029.001.14 and camt.055.001.13 (the Cash Management
business area). Captured 2026-10-08 from the **staging** ISO 20022 MCP, after its `get_spec_snapshot` gained simple-type facets
and external code definitions. The generator reads only the files in `fixtures/`.

## Which messages
The latest version of each family: the account report, statement and debit/credit notification messages (they share almost
all of their structure), the two payment cancellation requests, and the resolution of investigation that answers them.
`camt.055` is the successor of `pain.006`, which the pain batch left out for that reason. The repository lists about 100
camt message families in all; this is batch 1.

## How each kind of file was produced
| Files | Source | Method |
|---|---|---|
| `message.json`, `complex-types.tsv`, `snapshot-raw.tsv`, `choice-defs.tsv`, `codeset-defs.tsv`, `needs.json` | `get_spec_snapshot` (messages, components x8, choices, codesets x3, types) | **Generated by script** (`tools/spec-extract write`), never retyped. |
| `simple-types.tsv` | `get_spec_snapshot('types')` FACET rows | **Generated by script** (new: no `universal_lookup`). `spec-extract verify` re-derives the 77 simple types of all committed fixtures and finds 0 differences with the snapshot. |
| `codesets.tsv`, `codedefs.tsv` | enum names from `get_code_set_details`; wire values, ids and definitions from the snapshot | Enum names captured twice by independent agents and compared (147 rows: identical). Six code sets that publish no codes were read by hand from the same tool. |
| `rules/constraints-camt-batch1.tsv`, `rules/constraint-expressions-camt-batch1.tsv` | `universal_lookup` per scope and per rule | 128 scopes (97 components, 25 choices, 6 messages), 55 rules, 39 expressions. Captured twice by independent agents and compared: 0 differences in text or expression. One chunk (the two messages camt.029 and camt.055) had both agents build several expressions from a template, so it was captured a third time with a ban on templates: all three agree. |
| `camt029-v14/rule-codelists.tsv` | `get_code_set_details` | `InvestigationExecutionConfirmation4Code` (PECR, RJCR), named by a rule expression but not a type of any message. |

## What the new snapshot changed
- Simple-type facets are in the snapshot: the 63 types that existed in both old and new data agree on every pattern, length,
  digit count and bound.
- Two caam code definitions (`CryptographicKeyType5Code`, the two UKPT codes) now carry the spec's `|` paragraph marker where the old
  text had a space; the fixture and the translations were updated.
- External code sets carry their codes with definitions (3,314 codes in 140 sets). The library does not use them yet.

## New things these messages needed
- **YearMonth** simple type (`ISOYearMonth`): generated as text with the pattern `YYYY-MM` and a valid month.
- **Amount types** need a DATATYPE row of kind Amount in `complex-types.tsv`; the extractor now writes it. `ActiveOrHistoricCurrencyAnd13DecimalAmount` has 13 decimals.
- **Evaluator fix.** The spec writes `OriginalGroupInformationAndStatus[1]` for an element that occurs at most once. The evaluator treated
  `[1]` on a non-list as absent, so `ResolutionOfInvestigationV14.MessageOrGroupResolvedCaseRule` could never fail. `[1]` on such an element is now that
  element (behavior tests in `rules-camt.test.ts`).
- **Spec defect.** `UnderlyingTransaction37.GroupCancellationAndNumberOfTransactionsRule` counts `TransactionInformation`, which that type
  does not have (the rule was copied from `UnderlyingTransaction36`). It is reported unsupported (`rule_path_unknown`) and listed in `KNOWN_SPEC_TYPOS`.
- 55 new rules: 38 machine-checked (each shown able to pass and fail), 1 unsupported, the rest prose-only (guidelines, the supplementary-data
  rule and five rules that exist only as prose). Twelve rules reach through a list inside a list; each is checked by `rule-satisfiability.test.ts`
  and the case rules by `rules-camt.test.ts`.
- Source quirks kept as published: "must present", "ResolvedCase may be present at either ResolvedCase, ...", identical prose on three case rules.
