# Provenance of the pain.007, 008, 009, 010, 011, 012, 013, 014, 017, 018 fixtures

Captured 2026-10-06 from the **staging** ISO 20022 MCP. The generator reads only the files in `fixtures/`; the MCP is needed
only to refresh them (see `tools/spec-extract/README.md`).

## Which messages, and why not others
Latest version of each message family in the Payments Initiation business area, found by listing that area:
pain.007.001.13, 008.001.12, 009.001.08, 010.001.08, 011.001.08, 012.001.08, 013.001.12, 014.001.12, 017.001.04, 018.001.04
(pain.001 and pain.002 were done earlier).
**pain.006** (`PaymentCancellationRequestV01`) is not included: its `nextVersions` property points to
`CustomerPaymentCancellationRequestV01`, which now lives in the **Cash Management** business area (camt.055). The old
single-version `PaymentStatusReportV02` (pain.002.001.02) is an early version of the pain.002 family. No other latest pain
message has a `nextVersions` pointer.

## How each kind of file was produced
| Files | Source | Method |
|---|---|---|
| `message.json`, `complex-types.tsv`, `snapshot-raw.tsv`, `choice-defs.tsv`, `codeset-defs.tsv` | `get_spec_snapshot` (messages, components, choices, codesets, types; all pages) | **Generated by script** (`tools/spec-extract`), never retyped. Only types not already in an earlier fixture are written. |
| `simple-types.tsv` (`YesNoIndicator` in pain012, `Max10MbBinary` and `SkipPayload` in pain013) | `universal_lookup` | The snapshot lists simple types but not their facets (length, pattern), so these 3 were looked up. |
| `codesets.tsv`, `codedefs.tsv` (11 new code sets) | `get_code_set_details` | The snapshot has code values and definitions but not the enum names. External code sets are recorded as `*EXTERNAL*` (not enumerated), as before. |
| `pain008-v12/rule-codelists.tsv` | `get_code_set_details` | Two code lists referenced by rule expressions (`ChequeType3Code`, `ValidationRulePayCreditorByCheque1Code`). |
| `rules/constraints-sweep.tsv`, `rules/constraint-expressions-sweep.tsv` | `universal_lookup` per component, choice and message | See `rules/PROVENANCE.md`. |

## Verification
- The extractor was run on **pain.002** (hand-verified earlier by two independent captures): it reproduces all 146 type and
  member rows with zero differences, and its `message.json` is byte-identical to the committed one for both pain.001 and pain.002.
- Business rules: every one of the 182 scopes (125 components, 45 choices, 12 messages) was captured twice by independent
  agents and compared; see `rules/PROVENANCE.md`.
- The generator rejects any unresolved type name, so a missing or misspelled type fails codegen.

## Things found along the way
1. **Code set definitions in pain.002** were stored with a space where the snapshot has the spec's `|` paragraph break
   (5 external code sets). The snapshot is authoritative, so those 5 rows in `pain002-v15/codeset-defs.tsv` were updated.
2. **`LanguageCode`** (pain.013) publishes no codes, no length and no pattern; its only rule is "ValidationByTable". It is
   recorded as external with no length limits (any non-empty text).
3. **`Max10MbBinary`**: the 10 MB limit is stored as a character limit (10485760), which treats bytes as characters. A strict
   base64 byte check would be a refinement.
4. The snapshot has two simple types named `Exact2AlphaNumericText` and two code sets named `ExternalTransactorTypeCode`
   (different ids). Neither is used by any generated message.
5. **Rule `MandateAcceptance8.OriginalMandateIdentificationPresenceRule`**: the prose says "when Accepted is true" but the
   machine-readable expression applies when Accepted is **different from** true. We follow the expression, as for every rule;
   `packages/validate/test/rules-pain-family.test.ts` pins that behavior so a correction in the spec shows up.
6. Four pain.013 rules on `PaymentInstruction48` (cheque and creditor rules) have prose only, no expression; two rules
   (`ChargesAccountAgentRule`) compare to a pseudo-literal that is not a code value. These are reported as prose-only /
   unsupported and never guessed (`packages/validate/test/rulecoverage.test.ts`).
